Keeping it quiet

Fans follow temperature. Ocadox keeps the temperature down in four ways, all in Settings:

  • Profile: Silent, Balanced or Turbo. Silent paces replies and eases off as the graphics card nears 65 °C; Balanced at 75 °C; Turbo goes flat out.
  • Fan guard. Before each agent step, Ocadox waits until the card is below your temperature (60 °C by default). No admin rights needed.
  • Power cap (NVIDIA). Lowers the card's wattage only while a model generates, then puts it back. Needs administrator rights on Windows.
  • Your quiet week. In the thermals panel: how long Ocadox worked this week and how quiet it stayed, as a card you can share.

No graphics card: CPU mode

On an office desktop or a laptop with built-in graphics, models run on the processor. CPU mode turns on by itself (Settings > CPU mode shows why) and:

  • asks the model for less (a smaller context, no hidden thinking), so replies start sooner;
  • leaves one core free, so the mouse and windows keep working while it answers;
  • refuses a model too big for the free memory, instead of letting the PC freeze;
  • offers a processor limit (cores) and processor power (Reduced or Low: turbo boost off on Windows, a lower power limit on Linux after a one-time Allow).

Use a small model: qwen3:1.7b on 8 GB of memory, qwen3:4b on 16 GB. The model library labels what fits.

Project rules (AGENTS.md)

Put an AGENTS.md, OCADOX.md or CLAUDE.md in the root of your project folder. The agent reads it as standing instructions: how to build, test, what to leave alone. Two lines do more than instruct:

# AGENTS.md
Use pnpm, not npm. Keep components small.

Check: pnpm lint && pnpm test
After edit: npx prettier --write {file}
  • Check: what the agent runs before it says it's done (see below).
  • After edit: runs after every file the agent edits; {file} is that file. Handy for formatters.

Both go through the usual "run this command?" approval, unless you've set an auto-approve rule.

Helpers and self-checks

Helpers

For a big task, the agent can hand a question ("where is the login handled?", "why does this error happen?") to a helper that starts with a fresh, empty context and can only look, not change anything. It answers in a few lines, which keeps the agent's own context small: a big help with local models. Helpers run one at a time on the same model, under the same fan guard, so the fans stay calm.

Checking its own work

When the agent has changed files and thinks it's finished, Ocadox runs the project's check and hands any errors back to it to fix, up to twice. Without a Check: line it picks one: cargo check for Rust, tsc --noEmit for TypeScript, go build for Go, a syntax check for Python.

The agent's browser

To test a web app it's building, the agent can open it in a hidden copy of Chrome or Edge (whichever you have), click, type, and read the page and its console errors. Start your dev server, then ask, for example: "open http://localhost:5173, log in as test@example.com and check the dashboard loads without errors". Pages on your own PC always work; other websites only while web access is on (Settings).

From the terminal

ocadox run "fix the failing tests" --folder ~/code/app --model qwen3:8b
  • --folder the project (default: the current folder), --model the model (default: your bots' model).
  • --steps 30 the most steps, --quiet-level silent|balanced|turbo.
  • It asks y/N before commands and changes; --yes allows them all (for scheduled jobs you trust).
  • Ollama is reached at OLLAMA_HOST, or on this PC.

On Windows, the terminal doesn't wait for a windowed app to finish. Use start /wait ocadox run "…" in Command Prompt.

Bots, routines and triggers

A bot has its own name, chat, folder and model. Give it a job and close the window; the result is waiting when you come back. With Ocadox Pro, a bot can also work on its own with routines:

  • On a schedule: every day, weekdays, a day of the week, or every hour. It can wake the PC from sleep.
  • When files change in its folder: optionally only some files, like *.py or src/*.ts, *.tsx. It waits until saving has settled, then runs once and is told which files changed.
  • After a new commit: it's told which commit landed. Good for "review the latest commit".

A bot's own edits never set it off again. Turn on Save each result to get a file per run in its folder's Ocadox results.

Sharing bots

In a bot's editor, Share as a file saves a small .ocadox-bot.json: its name, look, instructions, starter prompts and routines. Never its folder or chat. To use one, choose New bot > From a file…. Routines from someone else arrive switched off; turn them on when you're happy with them.

The phone app

  1. Install the Android app from the releases page (the _android.apk).
  2. On the PC: Settings > Other computers > turn on "Let my other computers use this PC's bots" > Pair a computer or phone, and scan the code with the phone.
  3. Away from home: install Tailscale (free) on both and it keeps working, no router changes.

Full control: next to a paired phone, tick Full control to use the whole desktop app from it, running on the PC. Off, the phone has bots and chats only. Notifications work with the app closed (a quiet "Watching your bots" notification keeps it connected; switch it off on the list of computers).

Making images and videos

Settings > Image creation > Set up image creation downloads an image engine and the Z-Image Turbo model once (6.7 GB, every file checked). Then type /image_create and what you want, e.g. /image_create a lighthouse at dusk, oil painting. About a minute per image on a good graphics card. It needs 16 GB of memory on a PC without a graphics card. Already run Forge? Put its address in the same settings and Ocadox uses it instead.

Videos

Settings > Image creation > Video creation downloads the Wan 2.2 video model once (9.4 GB). Then /video_create a cat walking through autumn leaves makes a clip, or press Animate under any generated image to bring it to life. Choose the length in Make a video… (command palette), 2 seconds to 2 minutes, or type it: /video_create 30s a cat…. Over 5 seconds, the video is made as 5-second parts, each starting where the last ended, and saved as an MP4; write one line per scene for a storyboard. Each 5 seconds takes a few minutes and works the graphics card hard, so the fan guard and power cap apply. It needs a graphics card (12 GB or more is comfortable).

Speaking in your voice

Settings > Image creation > Speech, in your voice downloads Qwen3-TTS once (2.3 GB). Under Voices, add a 5–30 second WAV or MP3 of clear speech, give it a name and confirm it's your voice or you have the person's permission. Then:

/speak voice=Me Your tests all pass, and the fans stayed quiet.

Without voice= it uses your latest voice. Voices stay on your PC. Never use someone's voice without asking them.

Voice-overs

Press Voice over under a video (or Voice over a video… for a file). Type the script, or describe the video and press Draft with AI; pick a saved voice and whether to add captions. A short clip loops under a longer voice; a longer video holds its last frame until the voice ends.

Editing pictures and videos

Pictures: set up Picture editing once in Settings > Image creation (7 GB). Then press Edit under any picture and say what to change, or Upscale to make it 4 times bigger. Edit a picture… in the command palette works on your own files.

Videos: press Edit under a video, or Edit a video…. Describe the edit and press Fill in, or set it by hand: trim, shape (9:16 for TikTok, Reels and Shorts; 1:1; 16:9) by fitting over a blurred background or cropping, clips to join after it, music and its volume, and text on screen. Ocadox downloads FFmpeg once on Windows (115 MB); on Linux install it with sudo apt install ffmpeg.

Recording a website

Record a website… in the command palette: type the address, pick the length, desktop or phone size, and whether to scroll to the bottom. It opens in a private browser of its own (no sign-ins, nothing shared with your browser) and saves an MP4 you can edit or voice over.

Characters (AI influencers)

The Characters button in the top bar. Describe what your character looks like and press Make a portrait (or use a picture you have the rights to); add a personality, a saved voice and the Poster brand to post as. You'll be asked to confirm the face is made up, yours, or used with the person's permission.

  • New photo: say where they are and what they're doing; the face stays the same.
  • Bring a photo to life as a video, and make them talk in their voice.
  • Post it: your local model writes a caption in their personality, and the post goes to the Poster for your OK. Their AI label ("AI-generated character", which you can reword) is added unless you turn it off; platforms and advertising rules expect AI-made people to be labelled.
  • Bots: "every morning, make a new photo of Mia and post it" works as a routine.

Free has 1 character, Pro 5. Videos post to Mastodon, Discord (up to 10 MB) and Bluesky.

The Poster

The Poster button in the top bar writes, schedules and publishes posts.

  1. Accounts: connect each place, following the short instructions there (Mastodon: type your server and press Sign in with Mastodon; the others have a button that opens the right page: Bluesky an app password, Discord and Slack a webhook link, X your developer app's keys, Reddit a "script" app). Press Test to check it.
  2. Write a post: type it, or describe it and press Draft with AI (your local model). The counter shows the shortest limit among the places you picked (X 280, Bluesky 300). Attach an image, pick the accounts, then Post now or set a time and Schedule.
  3. Queue: posts waiting for your OK (from bots), scheduled ones, and what went out, with links. Failures can be retried.

Bots: ask a bot or the agent to "write a post about this release" and it drafts one into the queue. With Pro, tick Bots may post on an account to let them post there without asking (never Reddit, which bans automatic posting). A routine such as "every Monday, post what we shipped" makes it a weekly habit.

Limits: Free has 1 brand and 20 posts a month to Bluesky, Mastodon, Discord and Slack. Pro has 5 brands and 100 posts a month, plus X and Reddit. A post to three accounts counts three; the count resets on the 1st.

Git and GitHub

Tools > Git works on the chat's folder:

  • Changes: pick a file to see its diff; tick it to stage it (or Stage all).
  • Commit: type a message or press Write message to have your local model write one.
  • Push, Pull, Fetch, and a branch menu to switch or make a New branch.
  • Clone: in a folder that isn't a repository, paste an address (or pick from Show my GitHub repositories) and choose where it goes; it becomes the chat's folder.
  • Pull request: on a branch, Write it drafts the title and description; Open pull request pushes the branch and opens it on GitHub.

Signing in to GitHub uses what Git already has: on Windows, Git for Windows' own sign-in opens in your browser the first time you push or press Sign in with GitHub; the GitHub CLI's login (gh auth login) works too. Ocadox keeps no GitHub password or token of its own.

Cloud models (OpenRouter or your own key)

For the odd task a local model can't handle. Settings > Cloud models: turn them on, keep OpenRouter as the provider and press Sign in with OpenRouter; approve in your browser, then pick models from the list (search, prices per million tokens, and Agent-ready for models that can use the agent's tools). Or choose OpenAI, Anthropic or another OpenAI-compatible provider, paste your API key and the model names you want. They appear in the model list marked CLOUD. When you use one, your messages and the files the agent reads go to that provider, and it bills your account. The key is kept only on your PC. Off until you add a key.

Where everything is: the Tools menu at the top has video, picture editing, voice-overs, recording, Characters, the Poster and Git; Ctrl+K finds anything by name.

Something's wrong

Settings > Help > Send feedback or report a bug copies a short report of your setup (system, graphics, memory, CPU mode, Ollama and the loaded models, the last errors) and opens a GitHub form; paste it in and say what happened. It has no names, folders or chats, and you see all of it before sending.
